# 预编译工具链单一主分支设计及实施计划

## 目标

把原`darwin-arm64`、`linux-arm64`和`linux-amd64`三个长期分支整理为唯一`main`，并把各分支当前树放入同名顶层目录。主仓随后只登记一个子模块地址，按宿主目录选择安装程序与归档。

迁移必须满足以下条件：

- 保留三个原分支的提交历史。
- 保留每个平台当前树的内容、文件模式和Git对象。
- 复用本机已有仓库，不重新下载约7 GiB归档。
- 主仓本地与Docker入口按目录选择，失败时不改用系统工具。

## 目录接口

唯一分支的稳定目录为：

```text
darwin-arm64/
linux-arm64/
linux-amd64/
```

调用方先把系统和架构规范化为目录名，再使用：

```text
<host>/bin/cdh-toolchain install --repo <host> --dest <output>
<host>/bin/cdh-toolchain check --dest <output>
```

Linux目录额外提供`select`。Darwin继续使用明确安装路径，不扩展未实现的命令。

## 历史迁移

`main`从原Darwin分支建立，首个结构提交只为其当前树增加`darwin-arm64/`前缀。两个Linux分支分别作为独立归并提交的第二父提交，再用Git树前缀写入同名目录。这样无需复制或重新下载分片对象，也能从`main`追溯三个平台历史。

每棵导入树都通过Git树对象比较验证。比较发生在修改平台说明和版本之前，确保迁移本身没有改变归档、许可证、程序或源码。

## 主仓接入

主仓路径固定为`tools/toolchains`，组件统一维护该目录的源码、入口、生成器、测试与三宿主载荷；`.gitmodules`只登记远端、路径与`main`分支。本地首次接入从现有仓库克隆子模块工作树，再把登记URL改回正式私有远端，避免重复传输大对象。

主仓把安装结果写到`output/toolchains/<host>/`。类型化Go配置负责支持矩阵和展开后路径；最小Shell入口只在预编译Go尚未可用时规范化宿主并启动对应安装程序。Docker通过BuildKit命名上下文接收选定Linux目录，不在镜像构建期间访问私有Git仓库。

## 验证条件

- 三个目录的导入树分别与原分支树一致。
- 三个平台的`cmd`与`internal`包行为测试和`go vet`通过；平台原生慢测试由实际安装与对应宿主验证覆盖。
- macOS arm64安装、检查和版本探针通过。
- Linux arm64与Linux amd64安装程序在各自原生宿主或容器中通过检查。
- 私有远端默认分支为`main`，旧平台分支删除后只保留`main`。
- 主仓本地初始化、诊断和构建只使用展开目录。
- 两种Linux Docker构建不再安装或查找系统Go、JDK、Clang与LLD。

## 实施记录

迁移过程先在本地现有仓库创建`main`，逐个平台比较导入目录树，再按小提交推送。三个原分支均已成为`main`的可达祖先，三个导入目录树分别与原分支树一致。远端保持私有，默认分支已切换为`main`，旧平台分支已经删除。

三个模块的`cmd`与`internal`包行为测试和`go vet`均已通过。Darwin的`TestPayloads`会一次展开约16 GiB工具，实测超过Go默认10分钟及显式30分钟总时限，两次退出都发生在仍持续读取XZ分片时，没有功能断言失败。随后使用同一仓内arm64安装程序取消测试总时限完成实际安装，独立`check`、Go 1.26.8、Temurin 21.0.12.1+1、LLVM 19.1.7、LLVM 22.1.8、NDK Clang与LLD 21版本探针及Mach-O arm64架构检查全部通过。Linux原生慢测试随主仓两种Docker接入分别验证，避免在macOS执行异构程序。

主仓接入与本地、Docker消费切换按独立提交继续实施。完整跨仓任务拆分和命令记录维护在主仓`docs/plans/2026-09-12-预编译工具链单一主分支与主仓接入设计及实施计划.md`。
